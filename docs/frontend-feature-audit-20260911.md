## 대화 기록 아이콘 위치

홈에서는 **‘지금 뭐 할까요?’ 오른쪽**을 추천한다. 새 활동을 고르거나 이전 대화를
확인하는 동작이 같은 영역에 모이고, 캐릭터·배터리 영역은 현재 상태에 집중할 수 있다.
‘말풍선+이력’ 모양의 작은 아이콘에 **대화 기록**이라는 짧은 라벨을 붙인다.
충전 완료 시각이 있는 화면이므로 시계 단독 아이콘은 알림/타이머와 혼동될 수 있다.
투명 배경과 옅은 회색 선으로 보조 동작임을 표현한다.

채팅 화면에서도 필요하다면 **대화 영역 상단 오른쪽**에 같은 버튼을 둔다.
입력창 바로 위는 현재 대화의 후속 제안 버튼(`renderFollow`)을 위한 영역이므로
기록 목록 진입 버튼을 섞지 않는 편이 낫다. 기록은 아래에서 열리는 목록으로 제시하고
‘새 대화’와 날짜·첫 메시지 요약으로 구별하는 구성을 권한다.

이는 현재 화면에 대한 설계 판단이다. 아이콘에 짧은 라벨을 붙여 의미를 명확히 하는
원칙은 [NN/g Icon Usability](https://www.nngroup.com/articles/icon-usability/)를 참고했다.

## 현재 대화 이어보기와 기록 기능의 차이

`resumeBtn`은 숨겨 둔 현재 대화 DOM을 다시 보여줄 뿐이다. `goHome()` 초기화 시
새 thread ID를 생성하고 메시지를 지운다. 브라우저 새로고침 뒤의 기록 복원,
여러 대화 목록, 날짜별 조회 API는 없다.

서버에는 thread별 Context와 `InMemorySaver`가 있지만 프로세스 메모리이며,
HTTP 응답에 대화 목록이나 메시지 이력을 제공하지 않는다. 영구 저장되는 것은
승인받은 카테고리·체류시간 선호 JSON이다. 따라서 ‘대화 기록’은 버튼 교체만으로
완성되는 기존 기능이 아니라, 목록 조회·저장·복원을 추가해야 하는 확장이다.

근거: `web/index.html`의 `showHome`, `resumeBtn`, `goHome`;
`scripts/web.py`의 `contexts`, `session_summary`, HTTP Handler;
`src/voltgo/agent/agent.py`의 `InMemorySaver`; 설계서 §3.1.

### 과거 추천 카드의 구체적 위험

`core/feasibility.py`는 `plan_id=place.poi_id`로 생성하므로 조건 버전이 달라져도 같은
장소는 ID가 같을 수 있다. 프론트의 버튼은 `A 계획(카페명)으로 확정할게` 같은 텍스트만
보내고 카드의 version은 보내지 않는다. 따라서 사용자가 예전 ‘10분 체류’ 카드를
눌렀는데 모델이 현재 ‘20분 체류’ 후보를 선택하는 의미 불일치가 생길 수 있다.
이는 코드 흐름에 근거한 위험이며 실제 LLM을 호출해 재현한 결과는 아니다.
대화 기록에 예전 카드를 노출하기 전에 처리할 우선순위가 높다.

### 충전 목표 표시의 데이터 계약

현재 웹 서버는 `s.charging`과 시간 예산을 따로 전달한다. 원격 main도 계산 시
`_apply_target_soc()`로 보정한 임시 스냅샷을 사용하므로, 원래 차량 목표와 계산한
도달 목표가 언제나 같다고 가정할 수 없다. 예를 들어 차량은 90%로 설정됐고 사용자는
80% 도달을 요청한 경우, 80% 추정시각에 90% 라벨을 붙이면 안 된다.
`requested_target_soc_pct`, `effective_target_soc_pct`, `reported_target_soc_pct`처럼
뜻을 구분해서 웹에 전달하는 계약을 먼저 정하는 편이 좋다.
이번 대화에서 요청받은 80% 기본 표시를 임의로 변경하지는 않았다.

## 프론트만의 누락으로 분류하면 안 되는 부분

- **실제 지도 데이터:** 지도 SDK·마커·왕복 경로 UI는 작업 폴더에 있다. 하지만 현재
  웹 API에는 `map_data`가 없고, 원격 main/D 경로 클라이언트도 시간·거리만 추출한다.
  경로선 좌표 보관·전달과 브라우저 지도용 앱 키 설정이 아직 필요하다.
- **여러 대화의 영구 기록:** 저장·목록·복원 API를 추가해야 한다. 기존 선호 기억과 다르다.
- **남은 충전 시간의 수동 입력:** 설계서는 결측 시 질문을 요구하지만 현재 등록 도구에는
  사용자가 말한 remaining_sec를 스냅샷에 저장하는 명시적 인자가 없다. 입력창만 추가해서
  완성되는 기능으로 보지 말고 백엔드 입력 경로부터 정해야 한다.
- **자동 복귀 알림, 예약·결제, 차량 제어, 다중 장소 코스, 자동 로그인/토큰 갱신:**
  원본 설계서의 MVP 제외·확장 범위다. 구현 누락이라고 표시하지 않는다.

## 이미 프론트에 연결된 기능

추천 후보 카드, 시간 부족 안내, 자연어 조건 변경, 후보 선택/확정 결과, 선호 저장 승인과
거절, 저장된 선호 조회(정보 창), 선호 삭제 후속 버튼, Mock/추정/영업 미확인 경고,
배터리 잔량·충전 상태·예정 시각·목표선, 지도 UI, 뒤로가기/현재 대화 재개가 있다.
선호 설정 화면이 없다는 이유로 저장·삭제 자체가 미구현이라고 분류하지 않는다.

## 권장 순서

1. 현재 E의 승인 정책을 유지하면서 원격 main의 B/D 변경 및 필요한 A 변경을 통합한다.
   main으로 단순 교체하면 현재 E의 승인·만료 처리와 다른 동작이 될 수 있다.

4. 대화 기록의 보관 범위를 정하고 목록·복원 API와 기록 아이콘을 함께 구현한다.

이번 작업은 검토 문서만 추가했다. UI 변경, 브랜치 병합, 배포는 수행하지 않았다.
