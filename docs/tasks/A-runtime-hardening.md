# A 실행기 보완과 검증 정리

기준 main은 PR10 병합 커밋 `684728f45c2c9cd3fed0ec5927c04e7961efa622`다.
작업 브랜치는 `feat/a-runtime-hardening`이며 A의 진입점·응답 조립·웹 승인 연결과 재현 문서를 보완한다.

## 완료한 변경

- 입력 검사를 `ask()`의 graph 실행 전에 수행한다. 비밀값 형태·500자 초과·빈 입력은 checkpoint에 기록하지 않는다. middleware와 동일한 검사 함수를 사용한다. 웹은 HTTP 400으로 거부하여 브라우저 영구 기록에도 추가하지 않는다.
- `ask()`의 모델·실행 오류를 `AGENT_EXECUTION_FAILED` 응답으로 통일한다. 일시 오류 재시도는 기존 middleware의 1회 정책을 유지하고, 원본 예외 대신 예외 유형만 기록한다. CLI의 사용하지 않는 ClientError 분기를 제거한다.
- 승인 대기 중 새 질문을 공통 진입점에서도 차단한다. 웹 전용 승인 ID·소비 캐시와 중복 checkpoint ID 변환을 제거하고 Session의 `request_id` 원장을 사용한다.
- 웹 승인 재전송은 기존 `response`를 반환한다. 완료 후에도 원장을 유지하며, 과거 응답을 다시 조회해도 현재 대기 중인 새 요청과 화면은 보존한다. 서로 다른 결정/거절 사유는 409다.
- 출발 충전소 검색과 검색 반경 확대를 포함하면 마지막 안내까지 모델 9회가 필요했던 경로를 보완한다. 모델 8회 정책을 유지하고, 마지막 단일 도구의 검증된 `time_insufficient` 결과만 코드로 안내한다. 이전 턴 결과·오류·불완전 배치는 대체 응답의 근거로 사용하지 않는다. 다른 한도 초과는 계속 `LIMIT_EXCEEDED`다.
- ToolResult·ModelDecision·VoltGoResponse의 공개 필드와 PR10 대체 활동 판정·재검색 guard는 유지한다. Session 내부 ApprovalRequest에 새로고침용 화면 사본만 추가한다.

## 레거시와 테스트 정리

웹 `approvals`, `remember_approval`, 중복 `checkpoint_id` 변환 및 구형 `approval_id` 계약을 제거했다. 화면도 함께 `request_id`로 변경했다. `tools.py`의 미사용 datetime·timedelta·DWELL_DEFAULT_MIN import와 오래된 도구 수 설명을 정리했다.

웹 `decide` 전체를 가짜 함수로 바꾸어 500→409를 기대하던 검사는 실제 graph에서 저장 후 모델이 실패하는 검사로 교체했다. 이제 오류 응답 재전송과 저장 1회를 확인한다.

기존 별도 배포 문서의 `test_acceptance_extra.py`는 121초 승인 만료 검사를 중복하므로 새 배포본에 포함하지 않는다. TC12는 저장소의 실제 graph 120/121초 경계 검사를 직접 실행한다. 과거 제출·감사 자료는 이력으로 유지한다. 기존 Python 경계·격리·정책 검사와 PR10의 16개 검사는 각각 검증 목적이 있으므로 유지했다. 테스트 개수 자체를 줄이기 위해 정상 검사를 삭제하지 않았다.

실행기는 `scripts/run_cases.py`, 케이스 원본은 `docs/testing/test_cases.json`으로 통합했다. 전체 파일과 해당 파일의 개별 함수가 함께 선택되면 한 번만 실행한다. 문서 TC는 검사 묶음이며 pytest 개수와 같은 수치가 아니다.

## 호환성과 실행 범위

기존 웹 클라이언트의 `approval_id`는 `request_id`로 변경해야 한다. 저장소 화면은 함께 수정했다. 서버는 단일 프로세스 localhost 데모이며 웹 요청은 lock으로 직렬화한다. `ask/decide`를 직접 호출하는 통합자는 같은 Context/Session의 동시 실행을 직렬화해야 한다. 메모리 checkpoint·승인 원장·익명 세션은 서버 재시작 시 복원하지 않는다.

입력 차단 보장은 공개 `ask()` 진입점을 사용할 때 적용한다. build_agent의 raw graph를 직접 invoke하는 통합은 이 진입점을 우회하므로 같은 보장을 제공하지 않는다. 과거 버전이 이미 저장한 checkpoint를 소급 정리하는 마이그레이션은 없다.

오류 응답은 이미 실행된 부수 효과가 없었다는 의미가 아니다. 특히 저장 뒤 모델이 실패하면 선호 파일은 존재할 수 있으며 같은 승인 ID로 다시 실행하지 않는다. 일반 질문은 승인과 달리 재전송용 요청 ID 계약이 없다.

## 담당자와 함께 확정할 잔여 항목

이 변경은 다음 다른 영역의 동작을 완료했다고 주장하지 않는다.

| 협의 대상 | 남은 항목 | 확인할 기준 |
|---|---|---|
| B와 E | 충전 종료·목표 도달 때 이전 예산/확정 상태 무효화, 새로고침 표시 | 충전 중→중단 전환에서 이전 계획이 남지 않는가 |
| C와 D와 E | 외부 API 24회 경계와 배치 경로 호출, 캐시 재필터 허용 | 남은 호출량보다 큰 배치가 실행되는가, 캐시는 호출 없이 허용되는가 |
| B와 A | 사용자 목표 미입력 상태와 기본 80% 경고, 수동 잔여시간 입력 연결 | 차량 목표와 사용자 선택을 구별하는가 |
| D와 웹 담당 | map_data 및 보행 geometry 연결 | 실제 지도 선·왕복 경로가 표시되는가 |
| F와 각 API 담당 | 설계서 본문 최신화 및 실계정 시연 기록 | 기능/흐름/명칭과 실제 성공·제한을 일치시켰는가 |

현재 테스트 문서와 기록 양식을 제공하며, 원래 설계서 DOCX/PDF와 실계정 확인 결과는 담당자 취합이 필요하다. 실행 방법과 수용 기준은 [테스트 안내](../testing/README.md)를 따른다.
